# 评论治理运营链路 SOP

目标是让一条风险样本能被定位、判断、修订和重新验证。每次策略调整都应留下输入、变更理由、测试结果与回退方式。

## 一、日常闭环

| 环节 | 输入与动作 | 交付字段 | 验收条件 |
|---|---|---|---|
| 样本进入 | 接入评论及可见上下文，校验编号和必要字段 | 样本编号、来源批次、语言、正文、上下文、采集时间 | 缺字段单独进入异常队列；重复样本不重复计数 |
| 风险分流 | 按固定版本执行规则，输出风险、动作与证据 | 命中规则、风险分数、预测标签、动作、规则版本、处理状态 | 每条记录有结果；规则异常不能静默变成放行 |
| 标注与复核 | 依据准则一审、二审、裁决 | 两轮判定、证据、分歧类型、最终标签、准则版本 | 未裁决样本保留待办；不能当作已确认答案 |
| 策略对照 | 在同一冻结样本上比较基线和候选策略 | 样本集合版本、两版结果、差异清单、分组指标 | 两版使用相同分母；调参集与留出集分开 |
| 坏例归因 | 阅读错判原文与上下文，定位最小原因 | 错判类型、影响范围、责任模块、修复建议、负责人 | 能区分规则缺失、语境误杀、数据错误和政策空白 |
| 交接与回流 | 修正规则或补充样本，回跑回归测试 | 变更编号、关联样本、规则差异、验证结果、回退版本 | 修复原问题，并检查是否新增误杀或漏判 |

本地作品集实际展示合成样本、规则对照、标注状态、统计和导出；下面的灰度、政策协作与线上监控是后续接入业务时的执行方案。

## 二、协作交付

| 角色 | 主要负责 | 向下一环节交付 |
|---|---|---|
| 政策 | 判定边界、严重性、地区差异与争议裁决 | 适用范围、正反例、边界条件、动作要求、准则版本、生效时间 |
| 运营 | 样本抽检、标注质量、复核队列和坏例跟进 | 样本及证据、错误分布、分歧清单、优先级、建议修复范围 |
| 算法 | 召回与排序、模型评估、难例分析 | 模型版本、分组评估、阈值建议、已知盲区、输入输出约定 |
| 研发 | 数据接入、规则执行、权限、留痕和发布恢复 | 接口字段、错误码、幂等规则、监控、发布记录和回滚方案 |
| 产品 | 目标、优先级、处置体验与跨角色验收 | 需求范围、验收标准、冲突决策、试验设计与上线检查项 |

交接问题至少包含：样本编号、原文证据、预期与实际结果、出现版本、复现步骤、影响范围及验收方法。不能只写“模型不准”或“请优化”。

## 三、指标与分母

| 指标 | 计算方法 | 用途及限制 |
|---|---|---|
| 风险召回率 | 参考为风险且被复核或拦截的样本数 ÷ 全部参考风险样本数 | 衡量风险是否进入处置链路；不能只在命中样本里计算 |
| 拦截精度 | 参考为风险且被拦截的样本数 ÷ 有确认参考标签且被拦截的样本数 | 衡量拦截结果质量；分母为零时显示“无可计算分母” |
| 正常误拦率 | 参考正常且被拦截的样本数 ÷ 全部参考正常样本数 | 关注正常表达被直接限制的风险，与误送复核分开 |
| 风险直放率 | 参考风险且被放行的样本数 ÷ 全部参考风险样本数 | 直接暴露风险；进入复核不等于已经正确拦截 |
| 复核率 | 进入人工复核的样本数 ÷ 全部有效样本数 | 反映队列压力；不能单独作为效果好坏结论 |
| 动作一致率 | 预测动作与参考动作一致的样本数 ÷ 全部已确认参考动作的样本数 | 与风险类别识别分开；报告放行、复核、拦截的混淆情况 |
| 待办量、处理时长 | 按入队时间和完结时间计算 | 没有真实排队时间时不生成虚构时效数据 |

本项目将六类风险作为参考风险，“正常”作为参考正常。参考动作为空的待核项不进入质量指标分母，但复核率仍按全部有效样本计算。总体与分语言、分风险、分语境结果同时保留；比例以0—1存储，页面可显示百分比。类别很少时展示样本数，不能靠小分母排名。

## 四、坏例排查顺序

1. **先查数据。** 是否缺上下文、重复计数、参考标签错误、字段被覆盖、语言或版本不一致？
2. **再查语义。** 是否把引用当主张、把反对攻击当攻击、把方言当辱骂，或漏掉混合语言和变体？
3. **再查策略。** 是关键词过宽、否定范围错误、规则优先级冲突，还是阈值与目标不一致？
4. **确认影响。** 列出关联样本和相同模式，不只修复展示页上的一条案例。
5. **修复后重评。** 同时检查目标坏例、相邻正常例及冻结留出集，报告改善与退化。

指标突然下降时，先冻结发布并核对分母、流量组成、标签分布和日志完整性，再调查规则或模型。总体下降可能来自新语言或新话题占比变化，不能直接归因于算法能力退化。

## 五、版本、灰度与回滚

每次变更保存策略版本、准则版本、数据集合版本和代码版本，并附上变化说明。历史结果保留原版本，重新运行另建记录，不覆盖旧结果。

业务接入时按以下次序推进：离线对照 → 影子运行 → 小范围灰度 → 复盘后扩量。影子运行只记录候选策略，不直接改变用户处置；灰度规模、观察窗口和停止条件应在发布前确定。实验分组保持稳定，不能将不同人群的结果直接当作策略因果效果。

出现严重风险直放、正常误拦显著恶化、处理错误增加或队列超出处理能力时，暂停扩量，检查实际影响并按预定条件回滚。恢复到上一已知可用版本后，核对样本状态、处置结果和日志；已发生的处置不因策略回退自动恢复，需要单独复核与补偿流程。

## 六、一次迭代的收尾清单

- 问题和成功标准已明确，不用“整体提升”代替可检查目标。
- 所有差异样本都有归因；未解决问题有负责人和状态。
- 候选策略与基线在同一数据版本上完成对照，留出集未用于反复调参。
- 修改后的正常边界例和高风险例均完成回归检查。
- 发布、回滚、样本回流字段齐全；不将离线规则测试写成线上实验结果。
